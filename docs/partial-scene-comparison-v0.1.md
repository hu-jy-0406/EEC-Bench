# Partial scene comparison v0.1

Implemented pipeline: frozen entity outputs → two isolated single-shot graph extractions → cross-shot identity/anchor alignment → bidirectional visual evidence checks → deterministic comparison → evidence-preserving fusion.

## Usage

Run on a low-load compute node in an allocation already owned by guangyi.chen (see root AGENTS.md). No GPU is used. Existing configured Codex CLI and base Python with jsonschema are required.

```bash
python EECBench/scripts/run_partial_scene_comparison.py \
  --source EECBench/experiments/study_inconsistent_3/wedetect_shot_entities_20260912/run01 \
  --out EECBench/experiments/study_inconsistent_3/partial_scene_comparison_20260912/new_run \
  --policy EECBench/experiments/study_inconsistent_3/partial_scene_comparison_20260912/policy.json
```

Outputs must use a fresh directory. Default: gpt-6-astra, medium reasoning, two concurrent graph calls followed by one alignment and one evidence-check call. The default evidence prompt is partial_scene_checks_v0.2.txt, which checks sufficient local diagnostic witnesses without requiring full-object 3D projection. --checks-prompt partial_scene_checks_v0.1.txt retains the original pilot's stricter wording. No automatic retry or replacement of prior output. Failed raw responses, native events, known usage and status remain on disk. No instructions containing known anomalies or generation-negative prompts are sent to the visual models. The policy is consumed by the deterministic comparator, not the visual calls.

To rerun comparison without any model or image access:

```bash
python EECBench/scripts/compare_partial_scenes.py \
  --graph-a RUN/graph_shot1/graph.json --graph-b RUN/graph_shot3/graph.json \
  --alignment RUN/alignment.json --checks RUN/checks.json \
  --policy RUN/policy.json --out NEW_OUTPUT_DIRECTORY
```

## Structures

Eight strict JSON Schemas are exported under EECBench/schemas/partial_scene_{graph_inference,graph,alignment,checks,policy,comparison,memory,scene_view}.v0.1.schema.json. Inference contracts and semantic validators are in scripts/partial_scene_contract.py; scripts/export_partial_scene_schemas.py defines and exports the persisted graph/comparison/memory contracts. The graph_inference schema describes the raw model reply; graph includes frozen entities, frames and provenance.

- Graph: frozen nodes/frames, entity scope, anchor physical directions and image landmarks, per-entity/frame coverage, every unordered pair's review, sparse typed relation assertions covering every frame.
- Missing relation dimension is explicitly UNKNOWN. Pair review coverage is not proof of relational accuracy or all dimensions being resolved.
- Alignment partitions all local nodes exactly once into one-to-one matched, one-sided unmatched, ambiguous or scope-mismatch groups. Anchor correspondences have same/reversed/unknown orientation.
- Queries are generated by code, not selected by the reviewer: every unmatched node in either direction, every relation key with matched endpoints/reference in the union, and an explicit ledger of all unmappable relations.
- Presence checks record all target frames, source evidence, a target expected region and seven independent yes/no/unknown gates. No node omission becomes negative evidence.
- Relation checks record frame/region evidence and allowed value sets in canonical endpoint/anchor direction. Unknown is empty evidence; physical and axis-order domains are separate.
- Policy has an explicit default and per-entity overrides; invalid/duplicate IDs fail.

## Decisions

Identity agreement is separate from physical presence agreement. For presence, seen despite no matched node is observation_gap; absent at a defensibly mapped expected region is a conflict only if every gate passes and occupancy must persist. Confirmed non-observation through out-of-view/occlusion is complementary_view, but does not assert target-time existence. Otherwise unresolved.

For relations, camera-relative order is excluded. Same physical axes are normalized including reversed local subject/object order. Conflicting fresh evidence cannot overwrite independent graph facts: disagreements are extraction_evidence_conflict. Within-shot changes are retained as unresolved for the static comparator. Nonempty compatible value sets mean bounded compatibility; singleton agreement is shared_relation. Disjoint sets become conflicts only under must_persist; may_change gives explained_change and unknown gives continuity_unknown.

Fusion stores content-addressed original graphs, identity registry, compatible claims, conflict sets and unresolved records. Input graph import is idempotent and order-independent. Later observations do not fabricate earlier presence. The complete comparison retains policy, hashes, group IDs, query records, decisive frames and reasons.

## Current limits

This is a qualitative visual-evidence implementation. It does not fit local homographies, recover 3D or provide calibrated detection/visibility probabilities. Original-image endpoint/region coordinates are model judgments, not measured geometry. Ambiguous anchors are withheld, which can lower layout coverage. It does not enumerate all possible global identity permutations or solve a complete spatial CSP: ambiguous groups/anchors stay unresolved. It does not silently split collections or redetect missed entities.

Temporal rows are retained. The static comparator reports within_shot_change rather than localizing and comparing arbitrary dynamic trajectories. The Study 3 policy treats static furnishings/layout as unchanged, permitting person motion and narrated red-book removal; it is a declared case assumption, not general physical truth.

scene_view.json materializes global nodes and normalized, time-indexed assertions. Only matched identities merge; uncertain and scope-mismatched nodes remain separate. Source-only relations remain present. Negative assertions mean unchanged-source-occupancy is refuted, not global nonexistence. The HTML viewer includes original images, per-frame evidence boxes and all structured evidence. Structural and data checks are separate from browser rendering and semantic correctness. One real test does not establish accuracy or viewpoint invariance.

## Validation

Focused unittest fixtures cover missing/unknown versus negative evidence, all visibility gates, legal change, reverse queries, all-node/query accounting, unknown relation behavior, crosscheck disagreement, dynamic facts, symmetric contact, canonical anchor reversal, scope mismatch, policy typos, invisible assertions and fusion preservation. See the experiment run README and audit JSON for actual runtime results.

## Evidence recheck

recheck_partial_scene_evidence.py --source-run RUN --out NEW_RUN reuses frozen graph/alignment stages and records one new evidence call separately. Reused provenance usage must not be charged again; audit_partial_scene_comparison.py reports incremental_usage and new_model_calls. The original pilot remains intact. This is a versioned protocol diagnostic, not a controlled causal or accuracy improvement claim. Source-path metadata is kept on disk but excluded from new visual prompts; the first pilot included provenance directory names in its cross-shot inputs.
