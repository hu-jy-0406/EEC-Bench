# Codex 外观评价中的视角与共同可见部位（方案 v2，未实施）

2026-09-20。用户接受先前DINO分数解释，并明确VLM使用Codex；本次要求设计正面/背面等视角变化的处理。以下新增可见性、参考选择、比较与评分规则均为设计建议，尚未被选定或接入production。保留原DINO数值与已有身份、几何、存在性/空间处理。

## 目标与证据边界

同一global实体的正面与背面可能完全相容，即使整图DINO latent差异大。应判断共同可观察的固有外观是否矛盾，不能要求像素/投影形状相同。已匹配身份不能成为外观一致的证据；看不到的脸也不是一致的脸。全程仅使用提供的原始关键帧和原框，不生成假想正面、背面、纹理或中间帧作为证据。现有global registry的同scene匹配范围不因此扩展；跨场景关联仍需要另行授权实现与验证。

EntityBench依据：Appendix B.4 https://arxiv.org/html/2605.15199v1#A2.SS4 及官方 https://github.com/Catherine-R-He/EntityBench/blob/main/eval/evaluate_benchmark.py 。公开人物/物体pair prompt要求逐维度1–10和same判断，但未显式建模共同可见部位、每维度不可比较弃权、多视角参考连接。不能扩张成“所有EntityBench模块完全不考虑视角”：location prompt明确允许同一场景的不同角度。

## A. 先独立记录视角与可见性

对每个shot使用新Codex上下文，仅看本shot冻结实体/原图/原框，为每个appearance记录粗视角（front/side/back/oblique/unknown）、可见部位、遮挡/截断/模糊和证据。人物区分face、front_hair/back_hair、garment_front/back、left/right_sleeve等；物体用语义部位或表面，不强造固定front/back轴。发型、衣服等维度可以因部位不同而只部分可比。这里只描述可见性，不查看DINO分数、不比较其他shot、不作外观一致性结论。

可见性不能成为异常自我豁免：不能因为本应可见的脸/把手变没了就自动写成背面/遮挡。视角或遮挡解释必须有原图线索；证据不够明确标未知及原因。视角类别不根据颜色、款式、DINO特征聚类，防止把真正改变误分到“另一视角组”。

## B. 固定多视角参考与完整比较清单

将VLM单一全局参考扩为少量固定参考，人物首版front/side/back最多各一个；只有unknown视角也保留单独待评记录。每类选择最早达到固定清晰度/范围要求的实际appearance，决策只用时间、可见性、分辨率/模糊等信息，不能根据最终相似度/一致性挑选。选择结果在评分前冻结。DINO中心分数仍按已讨论算法计算，不因VLM参考库改变而改写。

1. 同视角：所有非参考appearance与对应视角参考比较。优先保持相同部位，原图证据不足者unknown，不能强制评脸。
2. 跨视角：不同视角参考之间也要比较。三个参考至多三组跨视角比较；不能只做各组内部比较便宣称全实体一致。
3. 桥接证据：跨视角比较可以读取同一实体在源/目标shot中额外的原始侧身或转身关键帧。按时间和可见部位选择，不能按是否支持高分挑选。只使用固定上限的小段原始证据（如每端至多两张），无证据时直接保留缺口。

基本比较量为N-R+R(R-1)/2，其中R是实际参考数；R<=3时约N，未含必要的无可比分支或未来专门漂移审计。视角描述阶段另有shot级Codex调用，不能宣称无额外开销。所有N次出现仍在表中；参考自身不拿自比较满分。额外witness并非新的独立评分样本，不按帧数重复加权。

同视角参考来自某shot，不保证它是正确外观。新视角首次出现不自动成为“真值”；跨视角参考检查及可见部位证据用于检查组间矛盾。无法连接的参考组只能说各自稳定，不能据此称跨视角外观已验证。

## C. 比较同一个部位，区分可比/未知/真实冲突

每次新Codex调用接收固定的一对appearance及已固定的少量真实witness、精确ID和相关正常剧情事实；不接收DINO分数、其他appearance的评分、身份review理由或预期答案。保持Codex当前配置的model/reasoning不降级，不直接套EntityBench的is_same逻辑。

每维度保存：共同部位、A/B观察、共同可见程度、score(1–10或null)、status(consistent/conflict/unknown/expected_change)、视角/光照/形变解释、具体frame/bbox证据和未排除的替代解释。

判定顺序：

- 两边是否显示同一语义部位/同一表面，或有原始桥接帧支持的可跨视角属性？
- 可见差异能否由旋转、透视、合理姿态/表情、光照、真实遮挡解释？
- 如果不能，是否存在直接可观察的固有颜色/纹理/结构/局部比例改变？
- 相关剧情是否明确授权该变化？保留原差异记录，仅豁免对应维度和时间。

只“可能是视角”不足以把冲突改成一致；明确的几何/遮挡解释可支持一致，无法判定归unknown。跨角度可比性不是简单的同名维度交集：衣服正面与背面可有天然不同颜色/印花；前胸logo在背面不可见不构成消失。反过来，在两边都能清楚看到的同侧袖子颜色明确改变，不能以“一个正面一个背面”整体豁免。

人物正面/背面示例：face=null；后脑勺对额前刘海不能直接比；共同可见的侧发/发色或原始转身证据可支持部分发型比较；两侧都清楚可见的同一肩缝/袖子可评衣服；整体轮廓只比较可由视角支撑的体型属性，不按像素宽度扣分。没有足够共同证据时整次比较可为unknown。

桥接不具有普遍传递性：A正面-B侧面可比脸，B侧面-C背面可比头发，不会推出A-C的脸一致。只在同一属性、同一部位有证据时扩展支持；identity track和运动连续性不能抹掉外观变化。所有witness都是输入事实而非新建虚拟视图。

## D. 输出与聚合

为避免同角度大量高分淹没跨角度问题，首版建议保留两项VLM结果：same_view_score与cross_view_score，以及每项分维度分数和证据数，不先加权成单一VLM总分。每项都由已冻结比较清单中的有效1–10分计算；unknown/expected_change不冒充满分，API失败单独记录。

每项内部先按维度在同一shot对内平均（同shot比较的shot对是s/s），再对有有效证据的shot对等权平均；维度均值可再等权汇总为该项分数。保存每维度有效/unknown/expected_change/failed数量、最差比较与参考IDs。比较边按无序appearance-ID对去重，不因重复用于witness增加权重。配对方法对得分有影响，必须冻结并在人类样本上验证。

部分维度高分不能被解释成全部外观已验证：比如cross_view_score=9.5只来自头发和袖子时，必须同时显示face未评。所有跨视角维度未知时cross_view_score=null，不记0/100。只有一个视角则跨视角项不适用。不开启现有空间coverage，也不改变现有presence计分。

DINO已接受的原始中心分保持原数。DINO低但Codex有充分对应部位/光照证据判一致，应报告“embedding对视角敏感，可比部位一致”；DINO高但Codex确认细节改变，保留外观冲突。两者不求max、不相乘、不把unknown修成高分。VLM为语义外观主判断，DINO为独立数值诊断；二者分歧可审计。

## E. 建议验证（尚未运行）

固定40–60个原始appearance比较，人工标明：视角变化但相容、相同部位真实改变、不同表面天然不同、遮挡/不可比、真实转身桥接及部件异常不能伪装遮挡。比较旧单参考prompt与新方案的视角误报率、真实变化漏报率及未知比例。包含高DINO变色例和低DINO正背面例，不以DINO分数先筛选评测对象。多视角参考/部位评分没有验证前不承诺准确率、耗时或成本。集合实体同样遵循成员/表面可见性，不把单成员框当整体。
