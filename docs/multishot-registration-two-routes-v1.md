# 多shot配准：增量prototype优化与Codex直接估计的评估

2026-09-22，用户要求评估两个方向；设计讨论，不是已实现/选定默认。优先讨论增量多个坐标组，不再将上一版“全场景联合优化”作为必需前提。生产两shot FPS32/codex_direct不变。

## 共用定义

prototype shot 是一个坐标组的参考shot；anchor实体是用于几何约束的稳定物体，两者不是同一个概念。同一语义场景可存在多个坐标组，每shot恰属一组，root变换恒等。单列只表示还没有可靠变换连接，不是另一个物理场景或不同实体。

两条路线输出共同接口：shot_id、coordinate_group_id、prototype_shot_id、status、source_to_prototype_transform（成功时）、failure/uncertainty及证据。各组内部可比较原始3D观测；不同组不能直接比较坐标/cosine/位移。身份判断仍可跨组使用原始图像，不能把无配准改写为无身份匹配。

## 路线1：anchor实体 + RoMa + 既有优化器

按manifest顺序处理：Shot1新建root；每个新shot按固定优先级尝试已有root，预先检查共享且可信的静止anchor/可用几何。对有条件的候选运行原6×6 RoMa、原置信度/双向检查/有效深度筛选、FPS最多32点、原等权未平方三维距离和目标，正尺度+gravity-yaw+平移。接受一个候选后接入该root，否则新建root。尝试过的shot对、原匹配及失败理由保存，不重复运行。

第一版推荐每个成员直接映射root，形成多个星形组；不自动把非root成员作为中介，也不强制后来的shot合并两个已建立坐标组。优点是最大限度复用当前pair实现、误差不沿配准链累积、旧坐标保持冻结。代价是一个shot可能只与某个非root成员重叠而无法匹配root，产生本可连接的多组；此外依赖处理顺序。

后续若覆盖不足，再研究“组内成员作备用连接”与“桥接合并两组”，此时必须记录复合路径与误差传播，不能称直接root配准。首次先量化分组是否过碎，不立即叠加全局优化。

成功/失败规则是实现前必须明确的内容。目前少于3有效对应点会失败，但>=3、有有限参数或优化器success不代表可信。建议单独记录：anchor依据、点数与空间覆盖/退化、数值收敛/边界解、选中点及完整池的尺度归一化误差。用稳定anchor上的证据评估，不用所有待评分实体的偏差作为注册质量，以免把真实连续性错误判成注册失败。未标定前不发明一个通用残差阈值或宣称高可靠。接受/拒绝整条配准的质量门槛不修改原点权/目标，也不按残差删点后重拟合。

昂贵的是RoMa；廉价的anchor预筛可免掉明显无约束的尝试。没有提前挑帧的生产优化，本设计不悄悄把36帧对降为更少。若最终k个root、m个shot，成功挂接m−k次，但总尝试可更多，最坏仍为m(m−1)/2；不能宣称一定线性。一个root的设置错误可影响所有成员，星形只避免多跳累积，不能避免共同系统误差。

## 路线2：增量Codex直接估计

参照 `scripts/register_gs_codex.py` / `prompts/gs_direct_registration_v1.txt`。旧版每次只看两个shot：正常情节、全部原图、各shot实体ID/name/motion_status、代表3D框、原始逐帧2D观测、坐标约定及相机内参/位姿；不提供跨shot对应、anchor清单、RoMa点、历史变换，不使用工具/数值优化。输出scale/yaw/translation，confidence及短理由。原scale范围0.1–10、Z-up yaw保持。

推荐多shot版本每次输入“新shot + 全部已有prototype shot”，一次请求选择一个有足够证据的prototype并直接输出新shot→该prototype的变换；均不可配则输出no_reliable_reference并新建root。每次新上下文，直接携带原始证据，不继承上次生成的解释。group编号/原型shot编号是调度元数据，不能当作已知几何关系。root自身原坐标可直接作为组坐标，无需向模型提供旧变换。

这样对于m个shot最多m−1次直接配准调用；prototype多时一次输入会变大，最坏累计证据仍可达到O(m²)。当前每场景最多8shots、每shot6帧，最大一次48原帧；需实测token与延迟，不承诺恒定20秒。若首先追求旧实验的严格可比，也可先保留两shot逐root调用作为对照，但它可能重复发送新shot。

模型应输出register/new_group二选一的严格schema：register必须有有效prototype和完整数值参数；new_group参数为null，不能以单位变换伪装成功。只保留注册结果、短依据/必要原帧引用、局限，不让其额外重做身份或一致性评分。当前旧schema强制输出数值，仅low/medium/high不足以承担新组判定，这一分支需新实现。

代码只做schema、有限数、正尺度、坐标约定和来源检查，不在背后用RoMa修正输出。模型confidence不是实测误差。给定相同场景/更多图像不保证能恢复缺少几何约束的变换；不应通过Prompt的“同一卧室”强行补出坐标关系。若给它全局实体对应/anchor清单，会成为另一种输入变体，不能混称旧纯Codex方案。

## 历史证据与建议

推荐增量优化作为可审计参考线，Codex增量原型选择作为速度候选；两者同一冻结检测/几何输入，分别完成，不自动互相fallback，不按最终评分挑方法。保留GeoCalib和原变换自由度，使比较聚焦注册方法。

已有Wan rank39四shot卧室是首例：如果无足够门口/床边共同静止约束，{Shot1,Shot3}、{Shot2,Shot4}两组是合理结果，不以强行合成一组为成功标准。需实际检测/匹配后验证，尚未跑此实验。

比较：坐标组数、实际可比shot/实体对覆盖、已知重现身份是否保留、可靠固定结构误差、歧义/失败是否诚实、原始几何和下游空间异常、墙钟/API tokens及费用。用相同共享点计算的拟合误差仅是拟合诊断，不冒称独立验证；尽可能补充人工对应或独立核验。第一测例评估natural gap，但仍需有真正桥接shot的另一例才能评估prototype星形的覆盖损失。
