# Shot-level prompt binding and targeted recovery v1

User-authorized implementation, 2026-09-22. Default integrated `--prompt-recovery auto` activates only when a prompt registry/alignment contract is supplied; `--prompt-recovery off` restores the previous path. No registry means no automatic invented schedule.

Sequence: original WeDetect and isolated clustering → isolated own-shot prompt binding → reverse required-entity/frame coverage check → Grounding DINO targeted candidates → isolated own-shot candidate review → frozen augmented inventory → existing geometry/motion/identity/scoring. No cross-shot evidence enters either shot reviewer. Unknown or missing observations are not absence verdicts. Prompt IDs never force cross-shot identity matches.

Grounding DINO uses the cached SwinT OGC model, box threshold 0.30 and text threshold 0.25. Query categories avoid requiring expected color/text/location, so inconsistent appearances can still be found. Only detector-produced original boxes may fill missing observations or form reviewed prompt-bound entities; existing positive boxes remain unchanged. Invalid boxes are excluded, not clipped. Every candidate has exactly one reviewed disposition. Whole-object/part scope uncertainty remains explicit.

Original entities stay in `case/entities`; accepted inventories live in `case/shot_prompt_recovery/entities`. Geometry preparation, registry provenance and appearance preparation resolve the active inventory. A failed recovery blocks downstream use. Global binding reuses unanimous confirmed local bindings; unknown/conflicting groups retain the existing model judgment. Recovery does not change matching or scoring gates.

CLI: `run_gs_integrated.py --prompt-recovery auto --prompt-recovery-device cpu` (plus normal required arguments). Device defaults to cuda; GPU execution still requires an idle allocated GPU and the existing UUID/resource guard. CPU does not require a GPU. Standalone `gs_shot_prompt_recovery.py --case CASE --registry REGISTRY --device cpu --grounding-python PYTHON` runs before geometry inputs are frozen. Explicit `--resume` validates source/input hashes, preserves failed attempts, and reuses successful calls; it is not permission to reuse stale geometry.

Parking validation: original frontend reused; fresh four bindings, 24-frame CPU detection and four accepted reviews, with one rejected review archived. Dynamic per-candidate schema now permits existing targets only when bound and missing that frame. 74 regression tests passed. All 94 original positive observations preserved; 41 new observations, seven new entities. Pillar recovered in all six frames of Shot1/2/4; Shot3 not required and not queried. Geometry input interface checked with old calibration, but new 3D inference/registration/spatial scoring were not run. Thus this validates recovery, not final spatial-anomaly recall.

CPU detection 163.905s; first binding to final corrected review 415.770s includes development delay. Original run, failed response, raw detector output and provenance are retained.
