# Study2 流程时间与 token 优化：结果及采用范围

## 结论

**没有同时达到“Shot1–Shot3 10–15 分钟、三个 shot 总开销约 $1、逐实体判断保持质量”的目标。** 已采用通过固定输入检查的保守子集：空间关系模型输入/输出压缩，以及 RoMa 与 CPU/API 判断并行。默认模型仍是 **GPT-6 Astra / medium**。

对齐后身份复核的压缩候选确实更快，但串联后改变了部分“未知／视角豁免”分类；没有作为默认方案。没有用总分碰巧相等来掩盖这些变化。原始 pipeline 可用 `--runtime-profile baseline` 恢复。

## 计费与计时范围

- 三个 shot 的预算口径：Shot1、Shot3 完整评测；Shot2 仅 WeDetect 和独立实体聚类。没有评测 1–2 或 2–3。
- 金额是官方 Standard 同步 API 价格等价估算，**不是 CLI 实际账单**；不含本地 GPU 费用。Astra 每百万输入/缓存输入/输出分别 $10/$1/$50，推理 token 已包含在 output 中。本轮缓存命中均为 0，各请求输入未超过 272K。
- 本轮固定原始 JPEG、检测/聚类和数值几何，重跑被修改的模型阶段。现有两个 GPU 分配都有常驻任务，没有争用 GPU。新全流程耗时由已完成的模型阶段和原 GPU 阶段耗时重建，**不是重新从 WeDetect 开始跑出的端到端墙钟时间**。
- Shot2 新跑了当前紧凑聚类：7 个实体，13,863 输入 + 277 输出，15.62 秒，约 $0.1525。采用原始六帧及冻结 WeDetect 候选；没有重新推理检测器。

## 整体比较

| 方案 | Shot1–Shot3 时间 | 三个 shot 总 tokens | 三个 shot API 等价成本 |
|---|---:|---:|---:|
| 原版 | 23分50秒（历史完整实测） | 670,623 | $8.39 |
| **当前默认：仅空间压缩＋安全并行** | 20分53秒（估算） | 529,986 | $6.89 |
| 全面压缩＋medium（候选，未采用） | 15分43秒（估算） | 517,846 | $6.35 |
| 全面压缩＋low（候选，未采用） | 13分03秒（估算） | 502,305 | $5.90 |

默认方案的 Shot1–Shot3 tokens 从 656,483 降到 515,846，降低 21.4%；三个 shot 成本降低 17.9%。

## 已采用的修改

1. **空间关系传输紧凑化。** 完整 canonical 输入、全部原图和定义几何数值仍保留。精确共享重复结构，列表改为字段表；可重构角点仅在误差 ≤1e-9 时用派生形式表示。模型输出使用短字段，必要时用原图附件索引和共享见证表；恢复原 canonical schema 后走原来的验证与计分门槛。
2. **并行调度。** 每 shot 几何完成后，原始 RoMa 图像匹配与动静判断、初始身份对应同时推进。只运行一个 GPU 阶段；筛选结构参照区域、抬升匹配点和求解配准仍等初始身份完成。原 RoMa 算法、36 组帧匹配、随机种子、点数和过滤逻辑不变。
3. **Shot2 明确停止在聚类。** 三 shot manifest 可直接传入；只有 Shot1/Shot3 进入几何、动静、身份和两项评分。总用量包含 Shot2，summary 单列其聚类数量。

当前默认保留原来的对齐后 A 复核和单次 B 判断。保留所有负 cosine 提案、局部支撑证据、原帧复核及 Prompt 因果复核；没有减少帧、实体、关系或见证门槛。

## 质量检查

当前默认的固定输入对照全部通过：

- 静止实体身份分组、存在性逐组分类与原版相同（上游代码/结果保持原版）。
- 所有 **28 对** cosine 与两个方向向量逐值完全一致；5 对负值、1 对通过局部证据。
- 存在性 **86.6667**：C=8、K=2、U=5、E=15；仍只确认台灯缺失、纸巾新增。
- 空间关系 **96.4286**：C=0、K=1、U=27、E=0；仍只确认杯子—笔筒，cosine = −0.5515472092139512。
- 非负 cosine 不被额外判定为已证实一致；未知不自动变成冲突。
- 三次新的空间模型调用通过原见证/支撑/Prompt 门槛。12 张原始 JPEG 哈希不变；42 份实验 payload 完成可逆传输检查；4 份完成的下游结果中全部 cosine/向量与原数值一致。见 [audit.json](audit.json)。

这是 Study2 的固定输入验证，不能据此宣称所有新视频质量绝不会变化。

## 没有采用的候选

### Astra 全面压缩

- low 独立阶段回放最初标签与原版一致，但这只是固定每一步输入的测试，不能代替串联验证。
- 英文短说明、短字段、匹配增量和见证共享可以缩短输出。对齐后复核从原来的 432.27 秒 / 14,146 输出 tokens，降到 low 的 161.99 秒 / 5,166 输出 tokens，medium 的 221.85 秒 / 7,086 输出 tokens。
- 三个错误配对仍拆分，三个确认冲突也仍保留。但 low 见证共享串联把 Shot1 小木桌及其植物由 unknown 改为 viewpoint/exempt，N 从 15 到 13，存在性分数变为 **84.6154**。
- medium 串联也把这两个实体改为豁免，同时把两组书列从 viewpoint/exempt 改为 unknown。四项互换使总 C/K/U/E 与分数恰好不变，**不能因此称逐实体结果一致**。
- medium 也发生变化，因此不能把变化全归因于降低思考强度；提示/输出表示及新生成的上游复核内容同样是变量。

这些边界分类有可讨论的视觉解释，但本轮没有足够依据证明其质量至少不低于原版，因此保留为实验配置，未默认启用。

### 便宜模型

- Luna low：Shot1 的四个静止实体变 unknown、Shot3 木椅变 moving；初始配对/参照改变；身份复核缺检查项。存在性虽然输出相同冲突标签，原见证门槛却把两项冲突降为 unknown；局部关系存在轴覆盖失败。因此淘汰。
- Terra low：Shot1 三个静止实体变 unknown；增加参照，并错误保留不同挂画、小木桌和盆栽的匹配。提高到 medium 的身份对照也未恢复原版分组。因此不整套替换。

仅把 Astra 降到 low 不会改变每 token 单价。最快候选的三个 shot 输出已有 21,995 tokens，光输出就约 $1.10，还没计算输入，因此现有证据量下无法承诺 Astra 全流程 $1。

## 复现、测试及异常记录

- 选中配置：`EECBench/configs/gs-runtime-profiles.v1.json` → `safe_spatial_medium`。
- 可回退：`run_gs_integrated.py ... --runtime-profile baseline`。
- 调度、失败停止、辅助 Shot2 范围、schema 别名及真实见证精确恢复测试：7 项通过；原集成 7 项、原单次 B 门槛 8 项通过。未新增改变评分语义的测试或校准阈值。
- low 后缀运行的 SSH stdout 中断发生在 B 结果保存后，确认进程已退出、调用成功后只继续空间阶段，没有重跑已付费调用。
- medium 身份返回一个未被引用的见证字典条目；原解码器将其误当致命错误。修正为保留原始条目、仅展开实际引用，并重新通过原 canonical 校验。复用了已完成响应，没有追加模型请求。非法引用和缺失见证仍失败；原失败状态保留在 `status_before_decoder_recovery.json`。
- 本轮优化验证共 43 次新模型调用，API 等价验证成本约 **$21.57**；这是多方案实验总开销，与表中的单次生产开销分开。
