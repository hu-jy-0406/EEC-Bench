# Optional single-survivor proposal-scope retention

This reference applies only when the request explicitly selects
`single_survivor_scope_retention_v0.1` under `physical_v0.6`. The default is
`disabled`. It supplements the complete physical verifier and revision contracts;
it does not replace their original-scope observations, identity questions,
physical-split challenges, graph protections, or evidence requirements.

An initial cluster can contain proposals that do not all correspond to one
supported physical entity. A supported subset need not be discarded merely
because the remaining proposals cannot be proved to describe another entity.
This policy permits at most one surviving accepted subset. The remaining
proposals stay uniquely accounted for without an accepted entity. They are not
newly confirmed physical units, evidence of absence, or detector votes.

## Verifier request

Use the explicitly selected extended verifier schema. Preserve every required
old report field and complete original-target review. Add the selected
`scope_retention_policy` and `retention_requests`; return an empty request array
when no eligible subset has sufficient evidence. Never fabricate a request to
fill the array or to force agreement with another role.

Consider only the supplied eligible parent IDs. Eligibility permits inspection;
it conveys no positive physical or identity judgment. Each parent must already
be an initial accepted cluster with at least two original proposals and cannot
be protected by deferred graph-partition lineage. A parent not supplied as
eligible cannot be retained through this path.

For each requested parent, identify a nonempty proper retained subset of its
original anonymous proposal IDs and the exact nonempty residual complement.
Preserve each original proposal's complete asserted content. Selecting a
proposal does not crop its meaning, correct a wrong referent, turn an assembly
into one of its members, or relabel it as a newly noticed object. A localization
correction is allowed only for the same original claimed content under the
existing protocol. A truly new object requires a separate discovery path.

Inspect the original frames for the retained scope. State confirmed physical
existence, graph worthiness, and one resolved proposal scope only when the
observations support them. Supply new `retained_evidence` with valid original
frame IDs, locators, uncertainty, and anonymous proposal IDs. Each cited
physical or scope witness must cover exactly the retained subset. A full-parent
observation cannot be relabeled as subset evidence. Category, source count,
confidence, box overlap, or a plausible name cannot supply that proof.

`physical_evidence_indices` reference physical-boundary, direct-interaction, or
temporal-continuity observations. `scope_evidence_indices` use those cues or
same-instance continuity. The same lawful observation may support both axes;
this is still one observation, not two independent votes. Support quality is a
description, not a numerical acceptance threshold. Evidence involving residual
or external proposals does not qualify as a retained-scope witness.

Set `residual_status` to `unresolved`. Do not invent another physical object to
make the complement look like an ordinary split unit. Continue to answer the
original complete-parent questions honestly, including unresolved judgments.
The two verifiers work independently and cannot see each other's requests.

## Consensus and revision

The orchestrator authenticates two successful isolated verifier calls and binds
their complete raw reports to actual distinct source/thread identities and
canonical report hashes. Old, failed, missing, duplicate, or differently scoped
reports cannot be reinterpreted as fresh retention proof. Private call provenance
stays outside model prompts. The extended raw report and the validated old-core
projection remain separate artifacts with their own hashes.

Only exact agreement on the parent and retained proposal set grants permission.
A missing request or disagreement grants none. This permission is separate from
ordinary physical-split consensus and cannot overlap it for the same parent.
No positive physical unit is synthesized for the residual.

The adjudicator receives the two current reports and a source-blind permission
summary. It may preserve the complete original parent, or use the exact
authorized survivor while regenerating the complete ledger. The survivor cannot
absorb another parent, surrender part of its authorized set, or be divided into
additional accepted entities. All residual proposal IDs must remain owned exactly
once by rejected or abstained records with `final_entity=null`. The accepted
count for that original parent cannot increase and cannot exceed one.

Permission does not accept the survivor. The final adjudicator must independently
confirm its complete retained physical content and identity scope from the
original pixels. Both verifier subset witnesses remain mandatory; revision
confidence or a new resolution cannot substitute for a missing verifier proof.
Protected graph-partition lineage and all remaining validation duties still apply.

A changed scope cannot inherit an old full-parent identity or whole-part/group-
member witness against an external accepted entity. Preserve the original pair
questions and inspect the exact final scopes. Use current exact-final-scope
relationship evidence or the existing exact-final-union distinctness proof as
appropriate. An unresolved accepted counterpart remains a review risk; a residual
record cannot be promoted later by graph composition or matching.

## Interpretation and audit

Record raw extended reports, validated core projections, source bindings,
consensus, actual ownership transitions, final gate decisions, and every paid
attempt under the selected policy. Preserve ordinary split audits separately.
An unchanged parent is a recorded unused permission, not an automatic success.
Do not expose private source identities, another shot, a semantic registry, or
expected comparison results to these roles.

This policy changes which already proposed scope can survive verification. It
does not repair shared visual mistakes, discover omitted objects, prove graph
composition, or establish robustness by itself. Approximate boxes and occlusion
are reported separately from entity existence and scope; a bounding rectangle
is not a segmentation mask, and hidden boundaries need not be invented.
