# FPS32 默认接入与 RoMA 优化空间

用户明确选择FPS32。register_gs_3d.py默认从有效anchor三维点池做联合端点归一化6D FPS，最多32对，基础置信度阈值0.2不变。所有选中点等权参与未平方3D欧氏距离总和，不按残差删除。3–31对时全部使用，少于3对明确失败。--sampling all保留全点比较入口。记录选中行、采样/优化分项时间、拟合子集误差和全池诊断；后者不能当作拟合目标或独立留出集。

集成入口显式传fps/32，源码快照包含采样实现，配置/文档同步。对齐后身份复核输入包含sampling来源。两个冻结测例回放的32行与变换参数完全复现此前FPS32实验（参数atol1e-10），原数据/历史结果未改。20项现有测试通过；另验证小点池和不足3对失败。CPU单线程、GPU隐藏、复用owned191764/node306，无新模型调用；没有重新运行下游身份/评分。

## RoMA 当前实际工作量

run_matching.py和CPU适配器均对6×6共36个帧对逐一match，precise档：低分辨率800×800、高分辨率1280×1280、双向匹配。每对model.sample(pred,5000)，再过滤同anchor区域、置信度>=0.2、cycle<=3px并提升到3D。

本地third_party/RoMaV2/src/romav2/romav2.py中match先产生稠密结果，sample再抽样。sample内部expansion_factor=4；5000输出点先抽20000候选，kde调用torch.cdist(x,x)构成20000×20000距离矩阵。降到1000对应4000×4000，矩阵元素数缩小25倍；这只说明该部分规模，不能推断整阶段25倍提速。大量全图dense预处理和神经网络前向不随输出点数变化。当前日志没有将前向与sample分开计时，二者贡献尚未测定。

## 建议下一步的独立实验（尚未运行或采用）

1. 每shot选3个具重叠和anchor可见性的代表帧，36→9对，减少75%模型调用；保持其他帧仍参与实体/身份流程。实际时间不是已测4倍，配准覆盖需验证。
2. 固定36帧对，sample5000→1000，分开记录match/sample/筛选/lift/FPS/优化时间，检查是否仍覆盖多个结构并在全部共同静止实体/非anchor上评价。不能在RoMA输出端直接只取32个，因为后面多层筛选会丢弃大多数候选。
3. 后续可降低推理分辨率或高分辨率细化，保留原始图像证据。官方fast设置同时关闭双向匹配，现有cycle检查不能原样使用；不能悄悄变更筛选协议。

官方说明：https://github.com/Parskatt/RoMaV2 （match为dense预测、sample为后采样，列有分辨率和bidirectional设置）。结论同时核对本地实际版本。
